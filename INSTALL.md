# Журнал регистрации приказов по видам деятельности
## Руководство по установке и настройке

Веб-приложение (Python + Flask + SQLite) для сетевой работы: регистрация приказов
в журналах «Опека», «Нуждаемость», «Профилактика», справочники, ролевой доступ,
отчёты с выгрузкой в Excel/Word и печатью, архивирование/восстановление,
обновление программы и журнал логирования.

Сборку программы в самостоятельные исполняемые файлы (без установленного
Python на целевом компьютере) для среды **Windows** и **ALT Linux** см.
в файле `BUILD.md`.

---

## 1. Системные требования

| Компонент | Требование |
|---|---|
| ОС | Linux / Windows / macOS |
| Python | 3.9 или новее |
| Свободное место | от 50 МБ (плюс объём базы и сканов) |
| Браузер пользователей | любой современный (Chrome, Firefox, Edge, Яндекc) |

### Необходимые Python-пакеты (см. `requirements.txt`)
- `flask` — веб-фреймворк;
- `openpyxl` — выгрузка отчётов в Excel (.xlsx);
- `python-docx` — выгрузка отчётов в Word (.docx).

## 2. Установка

1. Скопируйте каталог программы на сервер, например в `/opt/orders_journal`:
   ```sh
   sudo mkdir -p /opt/orders_journal
   sudo cp -r app.py run.sh requirements.txt templates static /opt/orders_journal/
   ```
2. Установите зависимости:
   ```sh
   cd /opt/orders_journal
   python3 -m pip install -r requirements.txt
   # при отсутствии прав: python3 -m pip install --user -r requirements.txt
   ```
3. Запустите программу (подробно — раздел 3):
   ```sh
   ./run.sh
   ```
   Каталог `data/` (база, сканы, архивы, логи) создаётся автоматически
   при первом запуске.

## 3. Настройка порта (важно!)

> **На данном сервере порт 5000 уже занят другой программой.**
> Поэтому приложение по умолчанию использует **порт 8080**
> (константа `DEFAULT_PORT` в начале `app.py`).

Способы задать порт (по убыванию приоритета):

```sh
./run.sh --port 8090          # 1) параметр командной строки
PORT=8090 ./run.sh            # 2) переменная окружения PORT
HOST=127.0.0.1 ./run.sh       # ограничение прослушиваемого адреса (по умолчанию 0.0.0.0 — доступ из сети)
./run.sh                      # 3) порт по умолчанию 8080
```

Если выбранный порт занят другим приложением, программа **автоматически
подберёт ближайший свободный порт** (начиная с запрошенного, до +100)
и сообщит об этом в консоли и в журнале логов. Фактический адрес будет таким:

```
http://<IP-адрес-сервера>:8080
```

Чтобы пользователи открывали программу по имени (без порта), настройте
обратное проксирование nginx (раздел 7).

Доступность из сети: если на сервере включён межсетевой экран, откройте порт:
```sh
sudo ufw allow 8080/tcp                       # Ubuntu/Debian
sudo firewall-cmd --add-port=8080/tcp --permanent && sudo firewall-cmd --reload   # CentOS/RHEL
```

## 4. Первый запуск и учётные записи

При первом запуске автоматически создаётся база данных и учётная запись администратора:

- **Логин:** `admin`
- **Пароль:** `admin`

⚠️ Сразу после входа смените пароль администратора: меню → имя пользователя
(«Моя учётная запись» / `/profile`) → смена пароля.

**Самостоятельная смена пароля сотрудником.** Любой сотрудник, имеющий логин,
может в любой момент сменить свой пароль без участия администратора: в шапке
сайта нажмите на своё имя («Моя учётная запись») и заполните форму «Текущий
пароль → Новый пароль → Подтверждение». Требования: новый пароль не короче
4 символов, не совпадает с текущим, подтверждение совпадает. Каждый успешный
факт (и каждая неудача) фиксируется в журнале аудита (`ПАРОЛЬ ИЗМЕНЁН` /
`ПАРОЛЬ НЕ ИЗМЕНЁН`). Пока сотрудник ни разу не менял пароль, установленный
администратором, при входе ему показывается рекомендация сменить пароль, а в
справочнике «Сотрудники» напротив его записи — пометка «(не менялся)». Если
администратор позже сбросит пароль сотрудника, рекомендация появится снова.

Дальнейшая настройка выполняется Администратором:

1. **Сотрудники** (`/employees`) — ФИО, должность, роль, а также логин и пароль
   для входа в систему. Роли: Администратор, Начальник отдела, Куратор, Опека,
   Нуждаемость, Профилактика.
2. **Виды приказов** (`/order_types`) — справочник наименований приказов,
   каждое относится к одному из видов (журналов): Опека / Нуждаемость / Профилактика.
   Редактировать справочник (добавлять, изменять, удалять незадействованные виды,
   загружать из Excel) могут **Администратор, Начальник отдела и Куратор**.
3. Права доступа к журналам:
   - Опека → роли «Опека», «Куратор», «Начальник отдела», «Администратор»;
   - Нуждаемость → роли «Нуждаемость», «Куратор», «Начальник отдела», «Администратор»;
   - Профилактика → роли «Профилактика», «Куратор», «Начальник отдела», «Администратор»;
   - Отчёты → «Куратор», «Начальник отдела» и «Администратор»;
   - Справочник «Виды приказов» (редактирование + импорт Excel) → «Куратор»,
     «Начальник отдела» и «Администратор»;
   - Справочник «Сотрудники» (редактирование + импорт Excel) → «Начальник отдела»
     и «Администратор»;
   - Сервис (архивация/восстановление/обновление), Журнал логов → только «Администратор».

   Роль **«Начальник отдела»** имеет полный доступ ко всем журналам, всем отчётам
   и всем справочникам (как администратор по данным); сервисные модули — за ним
   не зарезервированы.

## 5. Данные программы: каталог `data/`

| Путь | Назначение |
|---|---|
| `data/orders.db` | база данных SQLite (вся информация о приказах, справочники, пользователи) |
| `data/scans/` | загруженные PDF-сканы приказов |

Резервное копирование всего каталога `data/` достаточно для переноса/сохранения
программы. Восстановление из ZIP-архива доступно в интерфейсе («Сервис»).

## 6. Журнал логирования

Приложение ведёт подробный журнал событий:

- **Файл:** `data/logs/app.log`, кодировка UTF-8;
- **Ротация:** максимум 5 файлов по 2 МБ (`app.log.1` … `app.log.5`),
  настраивается в функции `setup_logging()` (`RotatingFileHandler`);
- **Что записывается:**
  - запуск сервера и выбранный порт;
  - `[HTTP]` — каждый запрос: метод, путь, код ответа, IP, id пользователя
    (уровень WARNING для ответов 4xx/5xx);
  - `[АУДИТ]` — значимые действия: вход/выход, создание/изменение/удаление
    приказов, сотрудников и видов приказов, отказ в доступе (403), попытки
    загрузки не-PDF сканов, резервное копирование, восстановление, обновление,
    смена пароля — с ФИО пользователя, логином и IP;
  - `[БЕЗОПАСНОСТЬ]` — неудачные попытки входа (неверный пароль);
  - необработанные ошибки сервера с полной трассировкой стека.

**Просмотр журнала в интерфейсе:** страница «📜 Журнал» (только Администратор) —
последние N строк (50–2000), подсветка предупреждений и ошибок, кнопка
«⬇ Скачать app.log», ссылки на скачивание ротационных файлов.

**Очистка журнала (только Администратор):** на странице «📜 Журнал» блок
«🧹 Очистка журнала» с выбором режима и кнопкой «Очистить»:

| Режим | Действие |
|---|---|
| **С копией** (по умолчанию) | создаётся резервная копия `data/logs/app.log.ГГГГММДД_ЧЧММСС.bak`, затем текущий `app.log` обрезается до нуля и удаляются архивные файлы ротации (`app.log.1…5`) |
| **Только копия** | создается резервная копия `app.log.<дата>.bak`, ничего не удаляется и не очищается |
| **Полная очистка** | `app.log` обрезается и все архивы ротации удаляются без создания копии |

Очистка выполняется «на лету» без перезапуска сервера: обработчик лога
продолжает писать в тот же файл. Само действие очистки фиксируется в новом
(очищенном) журнале записью `[АУДИТ] ЖУРНАЛ ОЧИЩЕН` (кто, IP, режим, имя
копии, число удалённых архивов). Резервные `.bak`-копии при необходимости
можно скачать или просмотреть; со временем их рекомендуется удалять вручную
или переносить в архив. Другим ролям (Куратор, Начальник отдела и т.д.)
страница и операция очистки недоступны (403).

Просмотр в консоли сервера:
```sh
tail -f data/logs/app.log          # текущие события
grep '\[АУДИТ\]' data/logs/app.log # только действия пользователей
grep 'Неудачная попытка' data/logs/app.log.* # подбор по всем файлам
```

## 7. Автозапуск и постоянная работа (Linux — systemd, Windows — служба/Планировщик)

Создайте сервис `/etc/systemd/system/orders-journal.service`:
```ini
[Unit]
Description=Zhurnal prikazov
After=network.target

[Service]
WorkingDirectory=/opt/orders_journal
ExecStart=/usr/bin/python3 /opt/orders_journal/app.py --port 8080
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```
```sh
sudo systemctl daemon-reload
sudo systemctl enable --now orders-journal
sudo systemctl status orders-journal     # проверка
```

Обратное проксирование nginx (доступ по http://prikazy.<домен> без порта):
```nginx
server {
    listen 80;
    server_name prikazy.local;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 7.4. Автозапуск сервера на Windows

Сервер на Windows можно запускать вручную (`python app.py --port 8080` или двойным
щелчком `scripts\windows\start_server.bat`), но для постоянной работы рекомендуется
автозапуск. Готовые скрипты находятся в каталоге `scripts/windows/`.

**Способ A (рекомендуется): служба Windows через NSSM.**
Служба запускается при загрузке ОС (до входа пользователя), автоматически перезапускает
сервер при сбое и пишет консольный вывод в служебные логи.

1. Установите Python 3.10+ и зависимости: `pip install -r requirements.txt`.
2. Скачайте NSSM (https://nssm.cc/download), распакуйте `nssm.exe` (64-bit) в
   `C:\Program Files\nssm\` и добавьте этот каталог в PATH (либо положите рядом с проектом).
3. Откройте PowerShell **от имени администратора** и выполните из корня проекта:
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\windows\install_autostart.ps1
   # параметры необязательны:
   #   -AppDir "D:\journal"   — каталог с app.py (по умолчанию — каталог проекта)
   #   -Port 8080             — порт сервера
   #   -PythonExe "C:\Python312\python.exe" — явный путь к python.exe
   ```
   Скрипт зарегистрирует службу `JournalPrikazov` (тип запуска — автоматически), настроит
   перенаправление вывода в `data\logs\service.out.log` / `service.err.log` с ротацией и
   перезапуск через 5 секунд после сбоя, затем запустит её.
4. Управление: `Get-Service JournalPrikazov`, `Restart-Service JournalPrikazov`
   либо оснастка «Службы» (services.msc). Удаление автозапуска:
   `powershell -ExecutionPolicy Bypass -File scripts\windows\uninstall_autostart.ps1`.

**Способ B: задача Планировщика заданий (без NSSM).**
Если NSSM недоступен, тот же скрипт автоматически зарегистрирует задачу
`JournalPrikazov` с запуском `start_server.bat` **при входе пользователя в систему**,
с тремя попытками перезапуска и без ограничения времени выполнения. Сервер будет
работать, пока пользователь залогинен (окно консоли нельзя закрывать).
Можно выполнить и вручную: «Планировщик заданий» → «Создать задачу» → триггер «При входе
в систему» → действие «Запустить программу»: `python`, аргументы `app.py --port 8080`,
рабочий папка — каталог проекта; на вкладке «Условия» снять «Только от питания сети»,
на «Настройки» — «Перезапускать при сбое».

**Способ C: папка «Автозагрузка»** (простейший, без прав администратора): создайте ярлык
на `scripts\windows\start_server.bat` и поместите его в
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`. Минус — сервер работает только
пока пользователь в системе, окно консоли должно быть открыто.

Проверка после установки: откройте `http://localhost:8080` (или `http://IP-сервера:8080`
с другого компьютера), убедитесь, что страница входа отображается, и что в
`data\logs\app.log` появляются записи `[HTTP]`. Если порт занят — приложение автоматически
возьмёт ближайший свободный порт и сообщит об этом в `service.err.log` / консоли.

Также не забудьте открыть порт в брандмауэре Windows для доступа сотрудников по сети:
```powershell
netsh advfirewall firewall add rule name="JournalPrikazov" dir=in action=allow protocol=TCP localport=8080
```

## 8. Обновление программы

### 8.1. Пошаговая инструкция (через интерфейс, только Администратор)

1. **Подготовьте пакет обновления** — ZIP-архив с новой версией файлов программы
   (`app.py`, `templates/`, `static/`, `INSTALL.md`, `requirements.txt`). Файлы должны
   лежать в корне архива, а не во вложенной папке вида `gurnal-main/gurnal-main/…`.
2. **Создайте резервную копию**: «Сервис» → «💾 Архивирование» → «Создать резервную
   копию», затем скачайте полученный ZIP. Это позволит вернуть данные при сбое.
3. **Загрузите пакет**: «Сервис» → «⬆️ Обновление программы» → выберите ZIP-архив →
   «Обновить». Заменяются только файлы приложения; база данных `data/orders.db`,
   сканы PDF, резервные копии и логи **не затрагиваются**. Файлы `orders.db`,
   `secret_key.txt` и `version.json` из пакета игнорируются в любом случае.
4. **Мягкий перезапуск выполняется автоматически — выключать сервер не нужно**
   (подробности в файле `UPDATE_HOT.md`): приложение завершает старый процесс,
   а обёртка `./run.sh` (watchdog-цикл) или systemd (`Restart=always`) сразу
   запускает новую версию кода; простой сайта ≈1–2 секунды. Если установлен
   флажок «Только применить файлы», активируйте новый код позже командой
   `./run.sh restart` или `sudo systemctl restart orders-journal`.
5. **Проверьте результат**: новая версия отображается в футере всех страниц и на
   странице «Сервис»; откройте журналы, справочники и отчёты — ошибок быть не должно.

### 8.2. Что происходит «под капотом»

- Структура базы данных обновляется автоматически при первом запуске новой версии:
  недостающие таблицы, поля (например, `note` — примечание приказа, `pwd_changed_at`)
  добавляются без потери существующих записей (миграции выполняются функцией `init_db`).
- Если в новой версии изменился `requirements.txt`, перед перезапуском выполните:
  `pip install -r requirements.txt --upgrade`.
- Каждое применение обновления фиксируется в аудите: `data/logs/app.log`,
  строка `[АУДИТ] ОБНОВЛЕНИЕ ПРОГРАММЫ ПРИМЕНЕНО` с ФИО и IP администратора.

### 8.3. Откат обновления

Если после обновления что-то работает неверно:
1. восстановите резервную копию («Сервис» → «♻️ Восстановление из архива»);
2. верните прежние файлы программы (из старой копии проекта или репозитория:
   `git checkout <предыдущий коммит> -- app.py templates static`);
3. перезапустите сервер.

### 8.4. Обновление вручную (без интерфейса)

Замените файлы программы (кроме каталога `data/`) и перезапустите сервис:
```sh
sudo systemctl restart orders-journal
```

Перед любым обновлением рекомендуется создать резервную копию на странице «Сервис».

## 9. Загрузка данных из Excel

Программа умеет импортировать из файлов `.xlsx` (Microsoft Excel / LibreOffice Calc):

| Что загружается | Где | Кто может |
|---|---|---|
| Сотрудники (ФИО, должность, логин, роль) | Справочник «Сотрудники» → «Импорт из Excel» | Администратор |
| Виды приказов (вид + наименование) | Справочник «Виды приказов» → «Импорт из Excel» | Администратор, Куратор |
| Приказы в журнал (Опека / Нуждаемость / Профилактика) | Страница журнала → «📥 Загрузка приказов из Excel» | по правам доступа к журналу (свой сотрудник, Куратор, Администратор) |

Порядок действий для каждого случая одинаков:
1. нажмите **«⬇ Скачать шаблон»** — программа выдаст готовый `.xlsx` с нужными
   столбцами и примерами строк;
2. заполните лист (первая строка — заголовки, далее данные; порядок столбцов
   можно менять — программа ищет их по названиям);
3. выберите файл в поле «Файл Excel (.xlsx)» и нажмите «Импортировать»;
4. после импорта появится сводка: сколько записей создано, сколько пропущено
   и почему (дубликаты, неизвестные значения).

Особенности импорта приказов в журнал:
- столбцы «№ приказа» и «Дата приказа» необязательны: номер присваивается
  автоматически с суффиксом журнала (1-оп, 2-оп…), дата берётся текущая;
- если номера в файле без суффикса (`15`), он добавится сам (`15-оп`); счётчик
  журнала синхронизируется с максимальным загруженным номером;
- наименование приказа сверяется со справочником своего журнала; если такого
  нет — вид приказа создаётся автоматически (о чём сообщается в сводке);
- дубликаты (тот же номер приказа либо совпадение «дата + наименование + ФИО»)
  пропускаются — повторный импорт одного и того же файла безопасен;
- даты принимаются в форматах `ГГГГ-ММ-ДД`, `ДД.ММ.ГГГГ`, `ДД/ММ/ГГГГ`;
- скан-коды PDF через Excel не передаются — приложите их к приказам вручную
  после импорта;
- все импорты фиксируются в аудите (`[АУДИТ] ИМПОРТ ПРИКАЗОВ ИЗ EXCEL` и т.п.).

## 10. Частые проблемы

| Симптом | Решение |
|---|---|
| «Address already in use» / порт занят | программа сама подберёт свободный порт (см. консоль и `data/logs/app.log`); либо задайте свой: `--port 8090` |
| Пользователи не видят страницу | проверьте, что брандмауэр открывает порт (раздел 3) и что в браузере указан правильный IP и порт |
| Кнопки Excel/Word не работают | установите пакеты: `pip install openpyxl python-docx` и перезапустите |
| В консоли и логе появляются ошибки 400 с бинарным мусором (`\x16\x03\x01…`) | кто-то обращается к HTTP-порту по протоколу HTTPS. Начиная с версии 1.3.2 такие подключения распознаются и не пишутся в `data/logs/app.log`. Чтобы пользователи могли работать по https://, настройте обратное проксирование nginx с TLS‑сертификатом (раздел 7) или запустите приложение через waitress/gunicorn с TLS |
| Нужно сбросить пароль администратора | остановите сервис и выполните: `python3 -c "import sqlite3;from werkzeug.security import generate_password_hash as h;c=sqlite3.connect('data/orders.db');c.execute(\\"UPDATE employees SET password_hash=? WHERE login='admin'\\",(h('newpass'),));c.commit()"` |
| Что делал пользователь? | страница «📜 Журнал» (фильтр по слову АУДИТ) или `grep` по `data/logs/app.log` |
