# Журнал регистрации приказов по видам деятельности
## Руководство по установке и настройке

Веб-приложение (Python + Flask + SQLite) для сетевой работы: регистрация приказов
в журналах «Опека», «Нуждаемость», «Профилактика», справочники, ролевой доступ,
отчёты с выгрузкой в Excel/Word и печатью, архивирование/восстановление,
обновление программы и журнал логирования.

---

## 1. Системные требования

| Компонент | Требование |
|---|---|
| ОС | Linux / Windows / macOS |
| Python | 3.9 или новее |
| Свободное место | от 50 МБ (плюс объём базы и сканов) |
| Браузер пользователей | любой современный (Chrome, Firefox, Edge, Яндекc) |

### Необходимые Python-пакеты (см. `requirements.txt`)
- `flask` — веб-фреймворк;
- `openpyxl` — выгрузка отчётов в Excel (.xlsx);
- `python-docx` — выгрузка отчётов в Word (.docx).

## 2. Установка

1. Скопируйте каталог программы на сервер, например в `/opt/orders_journal`:
   ```sh
   sudo mkdir -p /opt/orders_journal
   sudo cp -r app.py run.sh requirements.txt templates static /opt/orders_journal/
   ```
2. Установите зависимости:
   ```sh
   cd /opt/orders_journal
   python3 -m pip install -r requirements.txt
   # при отсутствии прав: python3 -m pip install --user -r requirements.txt
   ```
3. Запустите программу (подробно — раздел 3):
   ```sh
   ./run.sh
   ```
   Каталог `data/` (база, сканы, архивы, логи) создаётся автоматически
   при первом запуске.

---

## 3. Настройка порта (важно!)

> **На данном сервере порт 5000 уже занят другой программой.**
> Поэтому приложение по умолчанию использует **порт 8080**
> (константа `DEFAULT_PORT` в начале `app.py`).

Способы задать порт (по убыванию приоритета):

```sh
./run.sh --port 8090          # 1) параметр командной строки
PORT=8090 ./run.sh            # 2) переменная окружения PORT
HOST=127.0.0.1 ./run.sh       # ограничение прослушиваемого адреса (по умолчанию 0.0.0.0 — доступ из сети)
./run.sh                      # 3) порт по умолчанию 8080
```

Если выбранный порт занят другим приложением, программа **автоматически
подберёт ближайший свободный порт** (начиная с запрошенного, до +100)
и сообщит об этом в консоли и в журнале логов. Фактический адрес будет таким:

```
http://<IP-адрес-сервера>:8080
```

Чтобы пользователи открывали программу по имени (без порта), настройте
обратное проксирование nginx (раздел 7).

Доступность из сети: если на сервере включён межсетевой экран, откройте порт:
```sh
sudo ufw allow 8080/tcp                       # Ubuntu/Debian
sudo firewall-cmd --add-port=8080/tcp --permanent && sudo firewall-cmd --reload   # CentOS/RHEL
```

## 4. Первый запуск и учётные записи

При первом запуске автоматически создаётся база данных и учётная запись администратора:

- **Логин:** `admin`
- **Пароль:** `admin`

⚠️ Сразу после входа смените пароль администратора: меню → имя пользователя
(«Моя учётная запись» / `/profile`) → смена пароля.

**Самостоятельная смена пароля сотрудником.** Любой сотрудник, имеющий логин,
может в любой момент сменить свой пароль без участия администратора: в шапке
сайта нажмите на своё имя («Моя учётная запись») и заполните форму «Текущий
пароль → Новый пароль → Подтверждение». Требования: новый пароль не короче
4 символов, не совпадает с текущим, подтверждение совпадает. Каждый успешный
факт (и каждая неудача) фиксируется в журнале аудита (`ПАРОЛЬ ИЗМЕНЁН` /
`ПАРОЛЬ НЕ ИЗМЕНЁН`). Пока сотрудник ни разу не менял пароль, установленный
администратором, при входе ему показывается рекомендация сменить пароль, а в
справочнике «Сотрудники» напротив его записи — пометка «(не менялся)». Если
администратор позже сбросит пароль сотрудника, рекомендация появится снова.

Дальнейшая настройка выполняется Администратором:

1. **Сотрудники** (`/employees`) — ФИО, должность, роль, а также логин и пароль
   для входа в систему. Роли: Администратор, Куратор, Опека, Нуждаемость, Профилактика.
2. **Виды приказов** (`/order_types`) — справочник наименований приказов,
   каждое относится к одному из видов (журналов): Опека / Нуждаемость / Профилактика.
3. Права доступа к журналам:
   - Опека → роли «Опека», «Куратор», «Администратор»;
   - Нуждаемость → роли «Нуждаемость», «Куратор», «Администратор»;
   - Профилактика → роли «Профилактика», «Куратор», «Администратор»;
   - Отчёты → «Куратор» и «Администратор»;
   - Сотрудники, Сервис (архивация/восстановление/обновление), Журнал логов → только «Администратор».

## 5. Данные программы: каталог `data/`

| Путь | Назначение |
|---|---|
| `data/orders.db` | база данных SQLite (вся информация о приказах, справочники, пользователи) |
| `data/scans/` | загруженные PDF-сканы приказов |
| `data/archives/` | резервные копии (ZIP), создаются через страницу «Сервис» |
| `data/logs/app.log` | **журнал логирования** (см. раздел 6) |
| `data/secret_key.txt` | ключ шифрования сессий (создаётся один раз) |
| `data/version.json` | версия установленной программы |

Резервное копирование всего каталога `data/` достаточно для переноса/сохранения
программы. Восстановление из ZIP-архива доступно в интерфейсе («Сервис»).

## 6. Журнал логирования

Приложение ведёт подробный журнал событий:

- **Файл:** `data/logs/app.log`, кодировка UTF-8;
- **Ротация:** максимум 5 файлов по 2 МБ (`app.log.1` … `app.log.5`),
  настраивается в функции `setup_logging()` (`RotatingFileHandler`);
- **Что записывается:**
  - запуск сервера и выбранный порт;
  - `[HTTP]` — каждый запрос: метод, путь, код ответа, IP, id пользователя
    (уровень WARNING для ответов 4xx/5xx);
  - `[АУДИТ]` — значимые действия: вход/выход, создание/изменение/удаление
    приказов, сотрудников и видов приказов, отказ в доступе (403), попытки
    загрузки не-PDF сканов, резервное копирование, восстановление, обновление,
    смена пароля — с ФИО пользователя, логином и IP;
  - `[БЕЗОПАСНОСТЬ]` — неудачные попытки входа (неверный пароль);
  - необработанные ошибки сервера с полной трассировкой стека.

**Просмотр журнала в интерфейсе:** страница «📜 Журнал» (только Администратор) —
последние N строк (50–2000), подсветка предупреждений и ошибок, кнопка
«⬇ Скачать app.log», ссылки на скачивание ротационных файлов.

Просмотр в консоли сервера:
```sh
tail -f data/logs/app.log          # текущие события
grep '\[АУДИТ\]' data/logs/app.log # только действия пользователей
grep 'Неудачная попытка' data/logs/app.log.* # подбор по всем файлам
```

## 7. Автозапуск и постоянная работа (сервер под управлением systemd)

Создайте сервис `/etc/systemd/system/orders-journal.service`:
```ini
[Unit]
Description=Zhurnal prikazov
After=network.target

[Service]
WorkingDirectory=/opt/orders_journal
ExecStart=/usr/bin/python3 /opt/orders_journal/app.py --port 8080
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```
```sh
sudo systemctl daemon-reload
sudo systemctl enable --now orders-journal
sudo systemctl status orders-journal     # проверка
```

Обратное проксирование nginx (доступ по http://prikazy.<домен> без порта):
```nginx
server {
    listen 80;
    server_name prikazy.local;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

Для Windows можно запускать `python app.py --port 8080` как обычную программу
или зарегистрировать в «Планировщике заданий» при входе в систему.

## 8. Обновление программы

Два способа:
1. **Через интерфейс** (только Администратор): «Сервис» → «Обновление программы»
   → загрузить ZIP-архив с новой версией файлов приложения (`app.py`, `templates/`,
   `static/`). Файлы базы данных, сканы, архивы и логи **не затрагиваются**.
   После обновления перезапустите сервер.
2. **Вручную**: замените файлы программы (кроме каталога `data/`) и перезапустите сервис:
   ```sh
   sudo systemctl restart orders-journal
   ```

Перед любым обновлением рекомендуется создать резервную копию на странице «Сервис».

## 9. Частые проблемы

| Симптом | Решение |
|---|---|
| «Address already in use» / порт занят | программа сама подберёт свободный порт (см. консоль и `data/logs/app.log`); либо задайте свой: `--port 8090` |
| Пользователи не видят страницу | проверьте, что брандмауэр открывает порт (раздел 3) и что в браузере указан правильный IP и порт |
| Кнопки Excel/Word не работают | установите пакеты: `pip install openpyxl python-docx` и перезапустите |
| Нужно сбросить пароль администратора | остановите сервис и выполните: `python3 -c "import sqlite3;from werkzeug.security import generate_password_hash as h;c=sqlite3.connect('data/orders.db');c.execute(\\"UPDATE employees SET password_hash=? WHERE login='admin'\\",(h('newpass'),));c.commit()"` |
| Что делал пользователь? | страница «📜 Журнал» (фильтр по слову АУДИТ) или `grep` по `data/logs/app.log` |
