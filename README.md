# Журнал регистрации приказов по видам деятельности

Сетевое веб-приложение (Python + Flask + SQLite): журналы приказов
«Опека», «Нуждаемость», «Профилактика», справочники сотрудников и видов
приказов, ролевой доступ, загрузка PDF-сканов, отчёты с печатью и
выгрузкой в Excel/Word, архивирование/восстановление, обновление программы
и журнал логирования.

**Полное руководство по установке и настройке — в файле [INSTALL.md](INSTALL.md).**
**Сборка в исполняемые файлы для Windows и ALT Linux (без Python на целевом
компьютере) — в файле [BUILD.md](BUILD.md).**

## Быстрый старт

```sh
pip install -r requirements.txt
./run.sh                # порт по умолчанию 8080 (порт 5000 занят другой программой)
```

Открыть в браузере: `http://<IP-сервера>:8080` — вход `admin` / `admin`.

Другой порт: `./run.sh --port 8090` или `PORT=8090 ./run.sh`.
Если порт занят — приложение автоматически подберёт ближайший свободный.

## Основные страницы

| Адрес | Назначение | Доступ |
|---|---|---|
| `/journal/opeka` и др. | журналы приказов + PDF-сканы | по ролям (+ Куратор, Администратор) |
| `/employees` | сотрудники, логины, роли | Администратор |
| `/order_types` | виды приказов | все |
| `/reports` | 3 отчёта: печать / Excel / Word | Куратор, Начальник отдела, Администратор |
| `/service` | архивация, восстановление, обновление | Администратор |
| `/logs` | 📜 журнал логирования (просмотр и скачивание) | Администратор |
| `/profile` | «Моя учётная запись»: самостоятельная смена пароля | все сотрудники |
| `/api/active_users` | JSON: активные пользователи для меню «👥 Онлайн» | Администратор, Куратор, Начальник отдела |

В шапке сайта Администратор, Куратор и Начальник отдела видят кнопку
**«👥 Онлайн: N»** — раскрывающийся список сотрудников, работавших в системе
за последние 5 минут (ФИО, роль, IP, сколько секунд назад была активность).
Список автоматически обновляется каждые 30 секунд; отметки активности
сохраняются в таблице `active_sessions` базы данных, поэтому список не теряется
при мягком перезапуске/обновлении программы. Настройка окна активности:
переменная окружения `ACTIVE_TIMEOUT` (секунды, по умолчанию 300).

Файл журнала: `data/logs/app.log` (ротация 5×2 МБ). Записываются HTTP-запросы,
входы/выходы, неудачные попытки входа, отказы доступа, все изменения данных,
резервные копии, восстановления и обновления. Администратор может очистить
журнал на странице «📜 Журнал» в трёх режимах: с созданием резервной копии
(`app.log.<дата>.bak`, по умолчанию), только копия без очистки, полная очистка
без копии; очистка выполняется без перезапуска сервера.

## История изменений

- **1.5.2 (2026-10-16)** — фильтры-воронки и сортировка по столбцам в журналах;
  выделение отдельных приказов и массовое удаление; отбор журнала по периоду с
  сохранением настроек для каждого пользователя; пакетная загрузка документов
  перенесена в раздел «Сервис»; администратор может менять пароль пользователя;
  справочник «Причины» и поле «Причина» в журнале «Опека»; новая логика отчёта
  «Распечатка журнала за период» (печать / Excel / Word, выборка по виду приказа,
  для «Опеки» — наименование + причина в скобках).
- **Новая логика отчёта «Распечатка журнала за период»** — печать, выгрузка в
  Excel и Word с выбором вида приказа (Опека / Нуждаемость / Профилактика) и
  сортировкой по дате, а внутри даты — по номеру. Состав столбцов: № п/п,
  № приказа, Дата, Ф.И.О., Наименование приказа, ФИО специалиста, Примечание.
  Для журнала «Опека» в столбце «Наименование приказа» выводится вид приказа
  плюс причина из справочника в скобках, например
  «Назначение опекуна (По состоянию здоровья)»; для «Нуждаемости» и
  «Профилактики» — только наименование приказа. Та же логика применяется в
  REST API `/api/v1/reports/journal_print`.
- **Выделение и массовое удаление приказов в журналах** — у каждой строки таблицы
  журнала появился чекбокс (в т.ч. «выделить все» в заголовке); при выделении
  показывается панель с количеством выбранных и кнопкой «🗑 Удалить выделенные».
  Перед удалением запрашивается подтверждение со списком номеров и предупреждением
  об удалении сканов; серверный эндпоинт `/journal/<журнал>/delete_bulk` удаляет
  только приказы текущего журнала, проверяет права роли и пишет событие в аудит.
- **Отбор журнала по периоду с сохранением для пользователя** — под поиском
  появились поля «С даты / По дату»; выбранный период сохраняется в БД отдельно
  для каждого пользователя (таблица `user_prefs`) и автоматически применяется
  при последующих заходах в этот журнал; сброс периода тоже запоминается.
- **Сортировка по столбцам в журналах документов** — заголовки столбцов таблицы
  журнала (`/journal/<журнал>`) стали кликабельными: клик сортирует строки по
  этому столбцу (▲ по возрастанию, повторный клик — ▼ по убыванию). Числа
  сравниваются как числа, поэтому даты (ГГГГ-ММ-ДД) и номера приказов вида
  «2», «9», «12», «12а», «105» упорядочиваются корректно; текст — без учёта
  регистра. Сортировка выполняется на стороне клиента и сочетается с
  фильтрами-воронками и общим поиском.
- **Фильтрация в журналах документов** — в каждом журнале приказов
  (`/journal/<журнал>`) над таблицей добавлена строка с «воронками» ⏷ для
  каждого столбца (№ п/п, № приказа, Дата, Наименование, Ф.И.О., специалист,
  Примечание, Скан). Клик по воронке открывает поле ввода; фильтр работает
  мгновенно на стороне клиента, не регистрозависимо, комбинируется по
  нескольким столбцам и с общим поиском; рядом показывается число отфильтрованных
  строк. Строка фильтров скрыта при печати.
- **Сортировка документов** — списки приказов (журналы, отчёты и API
  `/api/v1/journal/<journal>/orders`) сортируются по дате приказа, а внутри
  даты — по номеру приказа. Номер сравнивается как число (часть до дефиса),
  поэтому «2-оп» идёт раньше «10-оп», а не в алфавитном порядке.
