# Обновление программы без выключения сервера

Документ описывает, как обновлять «Журнал регистрации приказов» до новой версии
**не останавливая и не выключая сервер приложения** — пользователи теряют доступ
к сайту всего на ~1 секунду (момент мягкого перезапуска процесса).

Версии программы: номер текущей версии отображается внизу каждой страницы
и в разделе «Сервис» (`data/version.json`).

---

## Как это работает

1. **Файлы заменяются «на лету»** — обновление загружается ZIP-архивом прямо
   через веб-интерфейс (роль «Администратор», раздел «Сервис»). Программа
   копирует только свои файлы (`app.py`, `templates/`, `static/` и т. д.);
   база данных `data/orders.db`, сканы PDF, резервные копии и логи **не
   затрагиваются**. Файлы `orders.db`, `secret_key.txt`, `version.json` из
   пакета игнорируются в любом случае.
2. **Мягкий перезапуск без участия администратора.** После применения файлов
   приложение создаёт флаг-файл `data/restart_pending` и корректно завершает
   свой процесс. Обёртка запуска `run.sh` работает в режиме watchdog-цикла:
   она видит флаг и **мгновенно запускает новую версию кода заново** — сервер
   не нужно ни останавливать, ни запускать вручную.
3. Если приложение запущено как служба **systemd** с `Restart=always`, systemd
   выполнит то же самое автоматически (он поднимет процесс после самозавершения).

---

## Способ 1. Через веб-интерфейс (рекомендуемый, сервер не выключается)

1. Войдите в программу под учётной записью **Администратора**.
2. Откройте раздел **«Сервис»** → блок **«⬆️ Обновление программы (без выключения
   сервера)»**.
3. *(Рекомендуется)* Нажмите «Создать резервную копию» в блоке
   «💾 Архивирование» и скачайте архив — это страховка на случай сбоя.
4. Получите от разработчика ZIP-пакет новой версии. Убедитесь, что файлы в
   архиве лежат в корне пакета (не во вложенной папке вида
   `gurnal-main/gurnal-main/…`).
5. Выберите архив в поле «Пакет обновления (ZIP)» и нажмите **«Обновить»**.
   - По умолчанию включён автоматический мягкий перезапуск: через 1–2 секунды
     сервер сам поднимется на новой версии. Страницы на это время могут
     кратковременно не отвечать — это нормально.
   - Флажок **«Только применить файлы»** — если хотите отложить перезапуск
     (например, до конца рабочего дня). В этом случае новый код активируется
     позже командой `./run.sh restart` или `sudo systemctl restart prikazy`.
6. Проверьте результат: обновлённый номер версии отображается в футере страниц
   и в начале раздела «Сервис». Все действия фиксируются в журнале
   `data/logs/app.log` (метки `[АУДИТ] ОБНОВЛЕНИЕ ПРОГРАММЫ ПРИМЕНЕНО`,
   `[АУДИТ] МЯГКИЙ ПЕРЕЗАПУСК`).

**Требование:** сервер должен быть запущен одним из способов, поддерживающих
перезапуск:
- `./run.sh` (watchdog-цикл встроен; режимы: `./run.sh restart`,
  `./run.sh stop`, `./run.sh run` — однократный запуск без автоперезапуска);
- служба systemd с `Restart=always` (см. INSTALL.md, раздел «Автозапуск»).

Если сервер запущен просто командой `python3 app.py` (без обёртки), мягкий
перезапуск завершит процесс, и его нужно будет стартовать вручную — для таких
сред используйте способ 2 или настройте systemd.

## Способ 2. Команда перезапуска (файлы уже заменены / ручное обновление)

```sh
./run.sh restart        # мягкий перезапуск работающего сервера
./run.sh stop           # полная остановка
tail -n 20 data/logs/app.log   # убедиться, что сервер поднялся заново
```

При ручном обновлении без веб-интерфейса: распакуйте новый пакет поверх папки
проекта (не трогая каталог `data/`) и выполните `./run.sh restart`.

## Способ 3. Служба systemd

```sh
sudo cp -r new_release/* /opt/prikazy/      # кроме каталога data/
sudo systemctl restart prikazy              # перезапуск службой (~1 сек простоя)
```

С `Restart=always` достаточно и самозавершения процесса из веб-интерфейса —
systemd поднимет новую версию автоматически.

## Что происходит с данными и пользователями

| Объект | Поведение при обновлении |
|---|---|
| База `data/orders.db` (приказы, сотрудники, виды приказов) | Не изменяется; структура (новые поля/таблицы, миграции) обновляется автоматически при старте |
| Сканы PDF, резервные копии, логи | Не затрагиваются |
| Активные сессии пользователей | Сохраняются (ключ `secret_key.txt` не перезаписывается), повторный вход не требуется |
| Доступность сайта | Кратковременно (~1–2 с) на момент мягкого перезапуска |

## Откат, если обновление пошло не так

1. Восстановите прежние файлы программы из старой копии проекта (или запросите
   у разработчика предыдущий ZIP) и примените их тем же способом.
2. При необходимости верните данные: «Сервис» → «♻️ Восстановление из архива»
   (перед восстановлением программа автоматически создаёт страховочную копию
   текущего состояния).

## Частые вопросы

- **Нужно ли ставить новые библиотеки?** Если в пакете изменился
  `requirements.txt`, сначала выполните `pip install -r requirements.txt`,
  затем обновляйте программу — иначе при старте возможна ошибка импорта.
- **Обновление доступно кому-либо, кроме администратора?** Нет: модуль
  обновления и мягкий перезапуск разрешены только роли «Администратор»;
  попытки фиксируются в логе как отказ доступа (403).
- **Что если порт занят?** Приложение автоматически подбирает ближайший
  свободный порт (по умолчанию стартует на 8080, т. к. 5000 занят другой
  программой на сервере).
